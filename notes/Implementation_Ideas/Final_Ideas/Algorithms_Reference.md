# Algorithms Reference

Every algorithm, model and hyperparameter in the Stage 1-4 pipeline, read off
the implementation in `final_algorithms/matlab/` rather than the plan
documents. Where code and plan disagree, the code is what this file records.

Companion to [Tech_Architecture.md](Tech_Architecture.md) (how the pipeline is
deployed) and [Module3_Plan.md](Module3_Plan.md) (why the design is shaped

## 1. Stage 1 — quality gate

`final_algorithms/matlab/stage1/`. Driver: `runStage1.m`.

```
#1 Pixel dimension  -> fail exits
#2 FOV detection    -> fail exits
#3 Sharpness/contrast cascade -> fail exits
        |
   any borderline recorded along the way?
        |
#4 Enhancement (flat-field -> CLAHE) -> fail exits
        |
      PASS
```

A **fail** exits immediately. A **borderline** is recorded in
`borderline_sources` and the cascade *continues*, so a later fail still
rejects the image.

### 1.1 How borderline is decided

Only two of the three gates can produce it.

| Gate | Borderline? | Rule |
|---|---|---|
| #1 Pixel dimension | **yes** | `megapixels = w*h/1e6`: `< 0.3` fail, `0.3-1.0` borderline, `> 1.0` pass. Hard-coded, never calibrated. |
| #2 FOV detection | no | area-ratio then area-frac, both pass/fail only |
| #3 Sharpness cascade | **yes** | borderline if *any* of varLapNorm / TenengradVar / RegionMin is borderline |

Within #3, only three of the four metrics have a borderline band:

| Metric | § | Gates? | Bands |
|---|---|---|---|
| Brenner gradient | #3.2 | fail only | `< brenner_fail` -> fail |
| Variance of Laplacian (normed) | #3.1 | **yes** | fail / borderline / pass |
| specSlope | #3.1 | **no — records only** | the gate's status comes purely from the Laplacian |
| TenengradVar | #3.3 | **yes** | fail / borderline / pass |
| RegionMin | #3.4 | **yes** | fail / borderline / pass |

**specSlope deliberately does not gate.** It is the one focus metric that
retains real disease correlation after stratification (within-camera
rho +0.171, positive in all seven strata), so gating on it would reject
images *because the patient is sick*. It is recorded as a feature instead.

**RegionMin is retained** because it is the only metric in the cascade that
catches *partial* blur: five regions (centre + four quadrants), focus metric
per region, minimum across them. Global metrics average a locally-blurred
region away. It reuses #3.1's already-computed Laplacian samples, so it costs
five grouped statistics over an existing array.

### 1.2 Where the #3 thresholds come from

Not constants. `stage1SharpnessThresholds.m` looks up
`stage1_sharpness_thresholds.csv` by resolution string (`2416x1736`), falls
back to a `pooled` row, then to hard-coded placeholders.

The table is generated by `calibrateStage1Thresholds.m`:

| Setting | Value |
|---|---|
| fail threshold | **p2** within the resolution stratum |
| borderline threshold | **p10** within the resolution stratum |
| Brenner | fail only, no borderline column |
| Minimum stratum size | 20 images; smaller strata use `pooled` |
| Grade labels read | **none** — the table carries no label information |

**Why per-resolution and not global.** A single global floor acts as a camera
filter, and camera correlates with grade, so it silently rejects sick
patients — measured at 3.8% of grade-0 images against 12.9% of grade-4, a
3.4x skew. Calibrating within a resolution stratum removes most of it at zero
inference cost, since resolution is known at gate time.

Current calibrated table (n = 499, `pooled` row):

```
brenner_fail 1.649   lap_fail 0.000279  lap_borderline 0.000499
tenengrad_fail 0.317 tenengrad_borderline 0.850
region_min_fail 0.000211  region_min_borderline 0.000374
```

The placeholder constants that apply with no table present
(`brenner_fail = 50.0`, etc.) **reject every APTOS image** — Brenner scores
run ~2-40 against a floor of 50 — so running the calibration before
extraction is mandatory, not optional.

### 1.3 Enhancement (#4) — what borderline triggers

`enhanceBorderline.m` runs flat-field correction (#4.1) then CLAHE (#4.2), in
that order, on the borderline image. **If either stage fails, the whole image
fails** — a borderline image whose enhancement degrades it is rejected rather
than passed through degraded.

#### #4.1 Flat-field correction (`flatFieldCorrection.m`)

Normalises the image against its estimated illumination field, but **only
where illumination is severely low or high** — blanket enhancement scored
negative on average in Module 1 testing, while conditional correction applied
only to illumination failures scored +0.65.

| Constant | Value | Meaning |
|---|---|---|
| `FFC_SEVERE_LOW` | 0.35 | background / global median below this = severely dark |
| `FFC_SEVERE_HIGH` | 1.8 | above this = severely bright |
| `FFC_WHOLE_IMAGE_SEVERE_FRAC` | 0.9 | if this much of the FOV is severe -> **fail** |
| `FFC_MAX_CONTRAST_LOSS` | 0.25 | >25% drop in local contrast -> retain the original |

```
field      = estimateIlluminationField(green, mask)
relative   = field / global_median(green within FOV)
severe     = (relative < 0.35 OR relative > 1.8) AND mask

severe_fraction >= 0.9   -> FAIL ("whole_image_severe_illumination")
no severe pixels         -> pass, applied = false
otherwise                -> feathered correction below
```

The correction is **feathered** so only severely-lit regions move: the severe
mask is Gaussian-blurred at `sigma = max(H,W)/50`, normalised to [0,1], and
used to blend the gain toward 1 elsewhere.

```
gain          = global_median / field
blended_gain  = 1 + weight * (gain - 1)
corrected     = image * blended_gain      (pixels outside the FOV untouched)
```

**Revert on failure.** Local contrast is measured before and after; if it
drops by more than 25%, the original is retained and `applied = false`. This
guards the documented risk that background estimation suppresses low-contrast
retinal features — microaneurysms, vessels, haemorrhages — which is also why
denoising is banned from this pipeline entirely.

#### Illumination field estimation (`estimateIlluminationField.m`)

The field is low-frequency by definition, so it is estimated at **1/8
resolution** and upsampled — costs nothing, per the notes.

```
1. downscale to 0.125 (antialiased bilinear)
2. median filter, ksize = max(3, odd(min(w,h)/8))   <- suppresses vessels and
                                                        lesions before fitting
3. fit BOTH models to the low-res background:
     plane  : a*x + b*y + c          (directional brightness variation)
     radial : degree-2 polynomial in normalised distance from the FOV centre
              (vignetting)
4. keep whichever has the lower mean squared residual
5. upsample bilinearly to full resolution
```

Fitting both and choosing by residual is the answer to the notes' own
objection that plane and radial fits "may fail because of many features that
contradict the idea of uniform ascent/descent" — neither model is assumed to
win.

#### #4.2 CLAHE (`claheEnhancement.m`)

Applied to the **green channel only** (the strong retinal-detail baseline),
restricted to the FOV. Tries progressively milder parameters and accepts the
**first** that improves local contrast without degrading the image.

| Constant | Value |
|---|---|
| Clip limits tried | `[2.0, 1.5, 1.0]` (OpenCV scale), rescaled `/100` for `adapthisteq` |
| Tile grid | 8 x 8 |
| `CLAHE_MAX_SATURATION_INCREASE` | 0.02 absolute increase in saturated-pixel fraction |
| `CLAHE_MAX_NOISE_INCREASE` | 1.5, **relative to the contrast gain** |

Three acceptance checks, all of which must hold:

```
contrast_ok   : local_contrast(after) > local_contrast(before)
saturation_ok : saturation(after) - saturation(before) <= 0.02
noise_ok      : (HF_after / HF_before) / (contrast_after / contrast_before) <= 1.5
```

If no clip limit passes, the stage **fails** (`clahe_degrades_image`) and the
image is rejected.

> **The noise check is deliberately relative, not absolute.** CLAHE is a local
> gain, so high-frequency energy scales with it: on the Module 3 sample the
> mildest step raised contrast 2.3-2.7x and HF energy 2.9-3.2x. An absolute
> after/before ratio of <= 1.5 could therefore never pass alongside "contrast
> must increase", and every borderline image was rejected. What the check is
> meant to catch is noise amplified 1.5x *beyond* the signal.

**The clip-limit unit conversion is a judgment call, not a port.** OpenCV's
`clipLimit` is an absolute histogram-bin-count threshold; MATLAB's
`adapthisteq` `ClipLimit` is normalised to [0,1]. There is no exact
conversion. Dividing by 100 lands the mildest step (1.0 -> 0.01) on
`adapthisteq`'s own default and preserves the 2 : 1.5 : 1 progression.

#### Enhancement helper metrics

| Helper | Algorithm |
|---|---|
| `localContrast` | mean local standard deviation inside the FOV, via a 15 x 15 normalised box filter (`sqrt(E[x²] - E[x]²)`) |
| `saturationFraction` | fraction of FOV pixels at intensity extremes: `<= 5` or `>= 250` |
| `highFrequencyEnergy` | HF energy inside the FOV, used only for the CLAHE noise ratio |

#### Where the enhanced image goes

The enhanced image becomes `stage1Out.image`, which Stage 2 consumes. The
outcome is recorded as two columns, neither of which reaches the grading
network:

- `stage1_verdict` (S1-20) — pass / borderline
- `enhancement_applied` (S1-21) — bitfield: 1 = flat-field, 2 = CLAHE, 3 = both

They feed `applyConfidenceRouting.m`, which multiplies the calibrated
probability by **0.85** (borderline) and/or **0.90** (enhanced). Both
multipliers are placeholders. S1-21 exists because CLAHE cost 20% of
microaneurysm detectability in Module 1 testing — this flag is how Module 3
detects that effect instead of silently absorbing it.

### 1.4 The 21 Stage 1 columns

The cascade short-circuits on first fail, but the CSV needs every column for
every image. `extractStage1Features.m` recomputes whatever the short-circuit
skipped using a separately seeded RandStream, and reuses metrics the cascade
did compute so the row agrees with the verdict.

| Columns | Algorithm |
|---|---|
| `megapixels`, `aspect_ratio` | `w*h/1e6`, `w/h` |
| `area_ratio_s1`, `area_ratio_s2` | `areaRatioCheck` on the FOV mask |
| `black_region_pct` | `100 * mean(~fov.mask)` over the whole image (the *gate* samples only 10% of rows) |
| `varLapNorm`, `specSlope`, `brenner`, `tenengradVar` | mean of the metric over random squares sampled inside a disk of 0.75 x image height |
| `regionMin`, `region_centre`, `region_q1..q4` | five regions, minimum across them; quadrants counter-clockwise from top-right |
| `illum_plane_tilt`, `illum_radial` | `illuminationFit`: background at 1/8 scale, median window **0.4 R** (must exceed the optic disc at ~0.29 R, or the disc survives into the "illumination" field), then a plane fit and a radial fit in units of the retinal radius. `tilt = hypot(a, b)`; `radial` is the slope, negative for the normal centre-bright field. Two fits because **symmetric falloff is normal vignetting while asymmetric tilt is a fault**, and one number cannot separate them. |
| `local_contrast` | measured on the **original** image, divided by 255 |
| `saturation_count` | as a **percentage of FOV pixels** — a raw count scales with megapixels, which is camera identity |
| `stage1_verdict`, `enhancement_applied` | §1.3 |

**Stage 1 contributes zero model inputs** (decision D7). Module 1 features
alone reached AUC 0.707 for referable DR, and adding them to the Module 2 set
moved AUC only 0.910 -> 0.915. Within resolution strata, every sharpness
metric's apparent link to grade turns out to be the camera.

## 2. Stage 2 — segmentation and lesion candidates

`final_algorithms/matlab/stage2/`. Split deliberately in two:

- `extractStage2Candidates.m` contains **nothing from a fitted classifier**,
  so it is cached once per image (`data/module3_candidates/<id>.mat`) and
  reused across all five CV folds.
- `stage2FeaturesFromCandidates.m` applies step 5 (the classifier) per fold.

That split is what makes leakage-free cross-validation possible (§3.3).

### 2.1 The scale table

Every pixel constant assumes images are resampled so the retina radius is
exactly `TARGET_R`.

| Constant | Value |
|---|---|
| `TARGET_R` | 436 px (working-resolution retina radius) |
| `OD_R_PX` | 62 px |
| `DD_PX` | 124 px (one disc diameter) |
| `UM_PER_PX` | 1850 / 124 ≈ **14.9 µm/px** |
| `DME_RADIUS_PX` | 34 px (500 µm) |

### 2.2 Vessels

The vessel mask used downstream is `matched_filter_mask OR calibre ∈ {major,
1st branch, minor}`.

**(a) Matched filtering** — Chaudhuri-style oriented Gaussian cross-section
bank: σ 2.0 px, length 9, 12 orientations, binarised at p90.

**(b) Frangi multi-scale vesselness** — calibre comes from the **scale σ at
which the response peaks**, not from the blobness ratio `rb`. `rb` is
constructed to be scale-invariant and carries almost no width information.

| Setting | Value |
|---|---|
| σ floor | **2.7 px** — never lower |
| σ max | 6.0 px |
| Number of scales | 8 |
| β (blobness) | 0.5 |
| γ (structureness) | 15.0 |

The σ floor is load-bearing: adding σ = 1.2 px (18 µm, below the smallest
real vessel) moved measured branchpoints from 195 to **2,539**.

Calibre bands, anchored to the scale table (vessel width 40-150 µm =
2.7-10.1 px):

| Label | Class | Width |
|---|---|---|
| 0 | venous beading | > 10.1 px |
| 1 | major vessel | > 7 px |
| 2 | 1st branch | 4-7 px |
| 3 | minor vessel | 2.7-4 px |
| — | rejected | < 2.7 px |

**(c) Neovascularisation / IRMA — by fine-scale excess, not density.**

```
fine   = line_detector(green, L=9,  W=11)
coarse = line_detector(green, L=31, W=31)
excess = (fine > p92) AND NOT dilate(coarse > p92, 5x5)
nv_score = 100 * |excess| / |FOV|
```

Density alone was measured **wrong-signed** (rho −0.391); fine-scale excess
gives +0.438 and is stable across every sharpness band. Split into NVD
(within 1 DD of the disc centre) and NVE (elsewhere). IRMA and NV are *not*
separable on a colour fundus image — the distinction is depth and leakage,
which needs fluorescein angiography — so they are reported as one
abnormal-vessel class.

**Topology stats** — density %, component count, largest-tree %, total
length, fragmentation (`1000 * n / length`), and orientation coherence from a
Sobel structure tensor smoothed at σ 2.0.

### 2.3 Optic disc

Disc-mean brightness map with vessel pixels excluded, five candidate radii
spanning 3-15% of the FOV radius, competing on **centre-surround contrast**
restricted to the 5-12% anatomical plausibility band. Annulus outer factor
2.0; confirmation requires contrast ≥ 5.0.

Two measured failure modes are guarded against:

- **Raw disc-mean cannot rank radii.** A smaller averaging window always
  reaches a higher maximum, so the smallest radius won on all 464 images of
  the Module 3 sample — `od_radius_pct` came out a constant 2.85, below the
  5% floor, so `confirmed` was never true.
- **Contrast alone reverses the bias.** A wider annulus reaches further into
  dark retina and keeps growing, so the largest radius wins instead.
  Restricting the choice to the plausibility band leaves the contrast test
  doing the confirming.

> The code excludes vessel pixels because `Stage_2_CNN` specifies it. The
> companion review (M3) argues the opposite — vessels *converge* at the disc,
> so excluding them pushes the search away from the answer. That proposal is
> deliberately **not** applied; the task spec is Stage_2_CNN as written.

### 2.4 Fovea

Search fan from the OD centre along the axis toward the FOV centroid:

| Setting | Value |
|---|---|
| Axis tilt | ±25° |
| Distance range | 0.5x - 1.25x an expected 2.4 DD |
| Sampling | 11 angular x 20 radial |
| Score | darkest 6-px-radius patch wins |
| Confirmation | brightness increases radially outward at 0.15 and 0.3 DD |

One disc diameter comes from the **pinned constant**, not the localised OD
radius. Deriving it from `opticDisc.radius` collapsed the search: that radius
is the smallest candidate (~12 px), so DD came out ~25 px and the fovea was
searched 30-75 px from the disc rather than ~300. Every image then reported
0.24-0.60 DD against an expected 1.2-3.0, which also tilted the OD-fovea axis
the quadrant map is built on.

### 2.5 The five-step lesion pipeline

Applies to every lesion class. Steps 4 and 5 are **structurally mandatory**,
not optional hooks — measured across four components, every one that stopped
at step 3 failed and every one that added steps 4-5 worked.

```
1 preprocess        green channel, shade-corrected
2 subtract vessels  vessel mask dilated 3x3 for 3 iterations first
3 threshold         -> CANDIDATES (high recall, poor precision)
4 features          per-candidate measurements
5 CLASSIFIER        keep / reject
```

OD is masked at radius x 1.2 and the fovea at 0.5 DD before the search.

**Scale-matched structuring elements.** One SE cannot serve both an 8 px
microaneurysm and a 30 px haemorrhage, because closing only fills what the
line *bridges*:

| Class | SE length | Percentile | Area bounds |
|---|---|---|---|
| Microaneurysm | **L = 15** | p99 | 3 px to π(125 µm/2)² |
| Haemorrhage | **L = 41** | p96 | MA upper bound to π·17² |

The haemorrhage lower bound is set to the MA upper bound so the two classes
cannot double-count the same blob. Candidate labelling uses 4-connectivity.

**The 16 per-candidate features** (`lesionFeatureOrder.m`) — note that
**no absolute intensity appears anywhere**:

| Group | Features |
|---|---|
| colour | `b_over_g`, `r_over_g`, `saturation` |
| edge | `grad_mag_rim`, `edge_sharpness`, `boundary_smoothness` |
| shape | `area_px`, `perimeter_px`, `circularity`, `eccentricity`, `solidity` |
| location | `dist_od_dd`, `dist_fovea_dd`, `dist_vessel_px` |
| context | `local_contrast`, `bg_ratio` |

**Why ratios and not absolute R/G/B.** A microaneurysm classifier fed
absolute colour reported AUC 0.995 — it had learned **camera identity** (top
features `r_mean` 0.237, `b_mean` 0.204). Banning absolute intensity dropped
it to an honest 0.742, with shape and contrast rising to the top. White
balance, flash intensity and exposure all shift the absolute RGB of the same
lesion between cameras.

### 2.6 Quadrants and the 4-2-1 rule

Quadrants are anchored to the **OD-fovea axis**, not the frame axes.

| Column | Rule |
|---|---|
| `rule421_haem` | `haem_q_min > threshold` |
| `rule421_beading` | beading present in ≥ 2 quadrants |
| `rule421_irma` | NV/IRMA in ≥ 1 quadrant |
| `severe_npdr_flag` | any of the three |

The textbook constant (>20 haemorrhages per quadrant) does not transfer — it
fires on 0/70 images at every grade, because it assumes a dilated seven-field
exam while this detector sees a single 45° field. Raw per-quadrant counts are
stored **unthresholded** so the constant can be refitted without re-extracting.

## 3. Stage 3 — grading

`final_algorithms/matlab/stage3/`. Driver: `runModule3.m`.

### 3.1 The grading network (MLP)

Regression on the ordinal grade, rounded later at fitted cutpoints — grades
are ordered, so predicting 4 for a true 0 is far worse than predicting 1, and
a softmax over five classes treats those errors as equally wrong.

```
featureInput(12-38, z-scored)
  -> fullyConnected 32 -> ReLU -> dropout 0.3
  -> fullyConnected 16 -> ReLU -> dropout 0.3
  -> fullyConnected 1   (linear -- regression, nothing follows)
```

| Hyperparameter | Value |
|---|---|
| Optimizer | Adam |
| Initial learning rate | **1e-3** |
| LR schedule | piecewise, x0.5 every 30 epochs |
| Mini-batch size | 32 (≈11 mini-batches per fold-epoch) |
| Max epochs | 200 (upper bound; early stopping ends it sooner) |
| Early-stopping patience | 20, on an inner 0.15 split of the training folds |
| L2 weight decay | 1e-2, decoupled, applied to `Weights` learnables only |
| Dropout | 0.3, both hidden layers |
| Weight init | **He** both hidden layers (ReLU); **Glorot** output; biases zero |
| Loss | MSE weighted per class |

**Class weighting.** `w_c = (N_train / 5) / n_c`, computed from what the fold
actually contains rather than hard-coded. Two code paths:

- every weight within 0.9-1.1 -> `trainnet` with plain `"mse"`
- otherwise -> a custom `dlnetwork` / `dlfeval` / `adamupdate` loop computing
  the weighted MSE directly

**Depth is fixed, width is tuned.** Two hidden layers, not one or three: one
wide layer concentrates overfitting risk, a third adds weights ~340 rows per
fold cannot support.

**Size check.** 38 inputs gives 1,793 trainable weights against about 340
training rows per fold — over five weights per example. Dropout, weight
decay, the decaying learning rate and early stopping are all **required**.

### 3.2 The RandomForest baseline was removed

Recorded because it overrides a plan decision. Module 3 grading is
**neural-network only**, at the project owner's explicit instruction. This
overrides decision D4 and §6.3, which made the forest a baseline the network
had to beat.

The consequence is kept in view rather than lost: on the previous 309 rows
the forest won decisively **within resolution strata** —

| Model | Referable AUC (within resolution) | QWK |
|---|---|---|
| RandomForest | **0.879** | **0.779** |
| MLP | 0.813 | 0.753 |

— even though pooled AUC ranked them the other way round, because pooled AUC
rewards learning the camera. With no baseline, Phase 5 reports the network's
numbers with nothing to judge them against.

The removal covers the **grading** model only. The lesion candidate
classifier is a separate component and still uses a bagged tree ensemble.

### 3.3 Lesion candidate classifier

The surviving tree model. Step 5 of Stage 2's pipeline, fitted inside Stage
3's CV loop.

| Setting | Value |
|---|---|
| Algorithm | `fitcensemble(..., 'Method', 'Bag')` — bagged tree ensemble |
| Trees | **200** (`NumLearningCycles`) |
| Min leaf size | **5** |
| Models | four separate: `ma`, `haem`, `hard_exudate`, `cws` |
| Weak labels | grade 0 = negative, grades 3-4 = positive |
| Grades 1-2 | **dropped from training**, still scored |
| Minimum data | 30 candidates and ≥ 10 in the minority class, else placeholder |

**Threshold selection, criterion fixed in advance:** sweep 0.05:0.05:0.95 and
take the **lowest probability at which the median per-image candidate count
on grade-0 training images is 0**. Choosing a threshold to maximise a
correlation and then reporting that correlation is circular.

**Placeholder fallback.** With no fitted model, `classifyCandidates.m`
min-max normalises each column and averages them into a 0-1 score. This is
explicitly *not* a trained classifier — it exists only so step 5 is never a
silent no-op.

### 3.4 The leakage-safe cross-validation loop

```
for each of the 5 dev folds:
    1. fit every lesion classifier on TRAIN rows only
    2. recompute lesion columns for TRAIN and the held-out fold with them
    3. fit z-score normalisation on TRAIN rows only
    4. train the grading network on TRAIN rows
    5. predict the held-out fold -> out-of-fold predictions
```

Steps 1-2 are why this is not a call to `crossval()`: candidate features are
cached per image, but the classifiers are refitted five times so no image is
ever scored by a classifier that trained on it.

**Why it matters.** Each lesion counter contains a classifier trained on weak
labels taken from the image grade. If it is fitted on an image and then
scores that same image, the lesion count already encodes the grade, and the
network learns the answer rather than the disease. This has already happened
once: the previous implementation's microaneurysm classifier trained on 250
images, and all 250 sat inside the 309-row feature table.

`RefitLesions=false` is a knowingly-leaky fast path for QC only.

### 3.5 Decision rules

All fitted on **out-of-fold predictions only**, then frozen before the test
set is touched.

| Rule | Algorithm |
|---|---|
| Cutpoints | **Coordinate ascent on QWK**. Initialised from score quantiles matching the true grade distribution; candidate positions are midpoints between consecutive unique scores (capped at 400); ≤ 50 passes. |
| Operating point | Walk the ROC descending, take the **first threshold where sensitivity ≥ 0.90**, read off specificity there. |
| Calibration — Platt | `fitglm`, binomial distribution, logit link |
| Calibration — isotonic | **PAVA** (pool-adjacent-violators), hand-written — MATLAB has no built-in isotonic regression |
| Calibration check | ECE before and after; "before" is measured on the min-max-scaled raw score, the only way to read it as a probability |
| DME override | `referable OR dme_flag` -> urgent referral, **overriding the grade** |
| Confidence routing | x0.85 borderline, x0.90 enhanced (placeholders) |

Fitted cutpoints exist because rounding a regression output pulls predictions
toward the middle grades: the previous model predicted grade 4 for only 3 of
61 true grade-4 images, calling most of them grade 3.

### 3.6 Which columns reach the network

Stage 1 contributes **zero** (D7). Of Stage 2's 45 columns, four are EXCLUDE
(raw coordinates `od_x/od_y/fovea_x/fovea_y`) and three are QC
(`od_radius_pct`, `od_contrast`, `od_fovea_dist_dd`), leaving **38 model
inputs** added in blocks rather than all at once — 38 inputs on ~340 training
rows per fold overfits.

| Block | Columns | Question it asks |
|---|---|---|
| 6a measured core | 12 | the baseline the finalized design can reproduce |
| 6b microaneurysm | +5 | does the MA block add grade-1 signal? |
| 6c calibre & beading | +5 | new, unmeasured |
| 6d NV split | +3 | does grade-4 recall improve? |
| 6e exudate & DME | +4 | **check the sign first** — the previous detector was inverted |
| 6f cotton-wool spots | +2 | new |
| 6g quadrants & 4-2-1 | +7 | the spatial rule |

Each block is kept only if **within-resolution** out-of-fold QWK improves.
The pooled figure partly measures the camera, so it must not be the deciding
number.

## 4. Stage 4 — CNN branch and report

`final_algorithms/matlab/stage4/`.

### 4.1 CNN architecture (`trainDrCnn.m`)

```
imageInput 224x224x3  (rescale-zero-one)
  -> [conv 3x3 x32  + BN + ReLU] -> maxpool 2, stride 2
  -> [conv 3x3 x64  + BN + ReLU] -> maxpool 2, stride 2
  -> [conv 3x3 x128 + BN + ReLU] -> maxpool 2, stride 2
  -> conv 3x3 x256                      <- named "features": the Grad-CAM layer
  -> BN -> ReLU
  -> globalAveragePooling -> dropout 0.4
  -> fullyConnected(5) -> softmax
```

| Hyperparameter | Value |
|---|---|
| Optimizer | Adam |
| Initial learning rate | 1e-3 |
| LR schedule | piecewise, x0.5 every 4 epochs |
| Mini-batch size | 16 |
| Max epochs | 12 |
| Validation patience | 5, validation fraction 0.1 |
| Augmentation | X/Y reflection, rotation ±15°, scale 0.9-1.1 |
| Class imbalance | **oversample minorities to the largest class**, so plain crossentropy works unchanged |

Trained **from scratch**: pretrained ResNet-18 weights are a support package
not installed on this machine. A small purpose-built network also trains
faster on CPU and keeps a **14x14 final feature map** at a 224 input, which
is what makes the Grad-CAM readable.

### 4.2 CNN data preparation (`preprocessForCnn.m`)

FOV bounding box from Stage 1's `buildFovMask`, padded to a square so the
resize does not distort the retina, then resized to 224. The black surround
is discarded because it differs by camera and is pure camera identity. No
Stage 1 gating or enhancement runs here — the CNN sees the image as captured,
and Stage 1's verdict stays a separate signal the report shows alongside it.

### 4.3 Explainability

Two maps, produced in parallel and shown side by side:

| Map | Source | Nature |
|---|---|---|
| Lesion evidence | Stage 2 detections | **causally grounded** — every hot region is a structure the report can name and count |
| Grad-CAM | CNN "features" layer, predicted class | gradient attribution — where the network looked |

Grad-CAM's known limitation is recorded rather than hidden: the last conv
layer is coarse, so each upsampled Grad-CAM pixel covers a large image
region while a microaneurysm is a few pixels. It cannot point at one. It is a
secondary sanity check; the lesion map is the primary evidence. Disagreement
between the two is itself a signal worth surfacing.

## 5. CSV population

Driver: `extractModule3Features.m`.

| Output | Contents |
|---|---|
| `data/module3_stage1_features.csv` | `id_code` + 21 Stage 1 columns |
| `data/module3_stage2_features.csv` | `id_code` + 45 Stage 2 columns |
| `data/module3_dataset.csv` | 6 metadata columns + 21 + 45 |
| `data/module3_candidates/<id>.mat` | cached classifier-free Stage 2 candidates |

Metadata columns carried but never used as features: `id_code`,
`diagnosis`, `split`, `cv_fold`, `resolution`, `sample_source`. `resolution`
is for stratification only — the network must never see it.

Images Stage 1 rejects get a Stage 1 row (for the per-grade rejection tally)
but **no Stage 2 row and no dataset row**. One bad image cannot stop a
500-image run.

The lesion columns written here use the **placeholder** classifier rule and
are for QC only. Module 3 refits every lesion classifier inside each CV fold
from the cached candidates (§3.4); training on these columns leaks the grade.

## 6. Constants that are not yet calibrated

Flagged in the code as placeholders. They run, but no measurement backs the
specific value.

| Area | Constants |
|---|---|
| Matched filtering | σ 2.0, length 9, 12 orientations, p90 binarisation — all placeholders |
| Frangi | σ max 6.0, 8 scales, γ 15.0 (the σ **floor** of 2.7 px is pinned and load-bearing) |
| Optic disc | search fractions 0.03-0.15, 5 radius steps, contrast threshold 5.0 |
| Fovea | expected distance 2.4 DD, min factor 0.5, patch radius 6 px, 11 x 20 sampling, radial check at 0.15/0.3 DD |
| Quadrants | venous-beading and NV/IRMA minimum 10 pixels per quadrant |
| Confidence routing | 0.85 borderline, 0.90 enhanced |

Two further divergences between the code and the companion reviews, both
deliberate and both flagged in the source:

- **Optic disc excludes vessel pixels** (Stage_2_CNN as written). Review item
  M3 argues vessels converge at the disc and should attract the search rather
  than repel it.
- **Fovea is darkness-only.** Review item M4 adds an avascularity penalty
  (`−3.0 x local vessel density`), on the grounds that darkness alone finds
  vessel shadows, which are darker than the foveal pit and far more numerous.
